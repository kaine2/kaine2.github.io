01 / 제작 포스트모템

드라고니아

빠른 공방에서도 읽을 수 있는 보스전

Unreal Engine · 개인 프로젝트 · 18p

전투 템포보스 패턴플레이 후 수정

거대한 보스와 공격권을 주고받는 3D 액션. 공격 전조, 반격 기회, 격돌과 지형 붕괴를 조정한 과정을 담았습니다.

기획 판단과 역할 살펴보기
본인 역할
목표 경험과 패턴 방향 설계, 수정 우선순위 판단, 직접 플레이 평가. AI는 구현과 검사 지원.
설계 판단
공방은 빠르게 유지하되 공격을 읽을 시간은 확보하도록, 준비 동작과 실제 휘두름을 구분했습니다.
읽을 내용

02 / 팀 프로젝트 기획서

데몬디펜스

배치한 뒤에도 판단이 이어지는 디펜스

Unity · 4인 팀 · 시스템 기획 · 31p

전투 규칙유닛 행동 AI데이터 구조

유닛 이동과 배치, 조합과 시너지, 강화 카드가 연결되는 전투 구조. 규칙을 플로우차트와 데이터 테이블로 구체화했습니다.

기획 판단과 역할 살펴보기
본인 역할
팀 프로젝트의 코어 전투·시스템 기획. 게임 흐름, 행동 규칙, UI와 데이터 구조를 문서화했습니다.
설계 판단
설치 후 관전하는 흐름에서 벗어나도록 유닛 이동을 열고, 크기와 시너지로 배치 판단을 만들고자 했습니다.
읽을 내용
기획 의도 5p · 게임 구조 7–8p · 전투·행동 AI 10–14p · 데이터 22–31p

기획 의도와 시스템 명세를 다룬 문서입니다. 모든 명세의 구현 완료나 플레이 성과를 뜻하지 않습니다.

04 / 제작 포스트모템

집으로 돌아가는 길

조합을 만드는 것에서, 꺼내 쓰는 경험으로

Unity · 개인 프로젝트 · 2026.09.03–09.16

속성 조합선택과 비용개선 가설

네 속성을 조합하는 2D 횡스크롤 액션 RPG. 조합의 다양성과 전투 중 교체 절차 사이에서 발견한 한계와 다음 개선 방향을 담았습니다.

기획 판단과 역할 살펴보기
본인 역할
기획과 플레이 판단, 스토리·배경 변경, 이동·점프 체감 조절. Claude Code는 구현 지원.
설계 판단
조합 창을 반복해서 여는 절차가 전투 흐름을 끊는다고 판단해, 저장한 조합을 전환하는 개선안을 제안했습니다.
읽을 내용
조합 규칙과 반응 → 플레이 중 발견한 불일치 → 교체 방식의 한계 → 개선·검증 계획

조합 전환 개선안과 외부 플레이 검증은 계획 단계입니다. 문서는 최종 정리 중입니다.

기획팀 주임
전투 · 시스템 기획

2025.05 — 2026.03
프로젝트 DRPC · 액션 RPG
01

상태이상 처리 규칙

25종의 상태이상을 Displacement · Immobility · ForcedAction · SoftCC로 분류하고, 중첩·우선순위·잔여 효과 처리 기준을 정의했습니다.

02

몬스터·보스 패턴

등장 구간에 따라 학습 → 적용 → 심화 흐름을 설계했습니다. 행동 트리는 draw.io로 시각화하고 쿨타임·피해 배율·상태이상을 테이블로 정리했습니다.

03

패링과 전투 체감

회피 외의 선택지를 주기 위해 패링 가능 시간과 각도, 성공 시 그로기와 실패 시 피격 규칙을 설계하고 구현된 전투를 플레이하며 조정했습니다.

04

스킬과 직군별 기획 전달

91종 스킬의 적용 효과·발동 모션·이펙트 방향을 레퍼런스와 함께 정리했습니다. 보스 외형과 동작은 시각 자료로, 이동 규칙은 시뮬레이션으로 전달했습니다.

05

경제 시뮬레이션과 가격안

Claude로 Excel VBA 시뮬레이터를 제작하고 재화 획득 흐름과 포션 가격안을 검토했습니다. 결과와 근거를 팀에 공유했으며, 해당 경제 기획은 게임 적용까지 이어지지 않았습니다.
